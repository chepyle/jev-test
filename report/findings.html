Zero-shot evaluation · LexGLUE + intent detection

Jev on legal and intent classification

TypeSafe's Jev answered every test question in LexGLUE's seven legal tasks without seeing a single training example. We compared it with GPT-5.6 Luna under the same instructions, with BERT fine-tuned on each task, and with Kev-4B, an open-weight model that serves the same API, then checked the pattern on two intent-detection benchmarks and on Kev's own test suites.

    Where the losses come from

    Jev's errors cluster on labels whose boundaries are conventions of the dataset rather than differences in meaning. A fine-tuned model learns these conventions from thousands of labeled examples; a zero-shot model sees only the label name.

        An open-weight look-alike: Kev-4B

        Kev is a family of open-weight models on Qwen bases that answer TypeSafe's System One API, so Kev-4B received exactly the requests Jev did. We served it ourselves on a Modal GPU with Kev's own deployment script. On Kev's own suites our served copy matched its published scores within 0.4 points, so the serving path is not what separates the two.

        The same pattern outside law

        BANKING77 and CLINC150 have fine-grained intents and published fine-tuned baselines. Jev trails on fine-grained intents, like LEDGAR, and beats fine-tuning at noticing that a request fits none of the intents, a judgment call like CaseHOLD.

        What was run

        Limits of these results

        • Different training regimes. BERT was fine-tuned on each task's training set. Jev and Luna saw no training examples.
        • Different protocols for Jev and Luna. Jev answers through TypeSafe's System One endpoint with per-label probabilities. Luna, which that endpoint does not serve, answers the same questions as JSON text, so it has no probabilities and no tunable threshold. Some of the gap between them may come from the protocol.
        • Threshold tuning is Jev only. It used validation data only, which the protocol allows, but Luna and BERT were not given an equivalent step.
        • One BERT seed. The reproduction lands within 1.1 micro-F1 of the published five-seed means, so differences under about one point should not be read as real.
        • Published baselines for the intent benchmarks. Those comparisons are not paired, and the BANKING77 baseline is BERT-large.
        • Kev-4B is not zero-shot everywhere. BANKING77 and the decision-v7 suite come from its training datasets. It also trained on inputs of at most 384 tokens, far shorter than most LexGLUE documents; the gap on short-input tasks (CaseHOLD, LEDGAR) shows length is not the whole story, but this study does not separate the two.
        • One Kev-4B serving configuration. bf16 on one GPU type, one checkpoint, one run.
        • Possible training-data overlap. Every dataset used here was public before these models were trained.
